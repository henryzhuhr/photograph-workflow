# Photograph Workflow PRD

## 结论

这个流程整体合理，适合做成一个轻量但可靠的照片工作流工具。推荐的关键顺序是：

1. 将相机存储卡中的 RAW 文件导入电脑。
2. 人工或半自动完成目录分类，并给目录命名。
3. 在 Lightroom 导入前，根据目录和自定义命名规则批量重命名 RAW 文件。
4. 将整理后的目录导入 Adobe Lightroom 进行筛选、评级和修图。
5. 从 Lightroom 导出成片。
6. 对当前拍摄项目目录打包压缩，写入归档位置。

其中最重要的边界是：文件重命名必须发生在 Lightroom 导入前。如果已经导入 Lightroom 后再改名，Lightroom 目录可能会丢失原始文件引用，后续修图和导出会变得不稳定。

## 产品目标

本项目要解决的是摄影后期前后的“文件管理可靠性”问题，而不是替代 Lightroom 的修图能力。

实现形态明确为 uv 管理的 Python 脚本项目，优先服务本地文件扫描、重命名预览、重命名执行和归档。MVP 不要求安装成系统 CLI，用户可以直接执行 `.py` 脚本。

核心目标：

- 降低从相机导入到归档之间的重复手工操作。
- 保证 RAW、XMP、导出成片、归档包之间的命名和目录关系清晰可追踪。
- 在真正修改文件前提供预览、冲突检查和回滚依据。
- 支持按个人习惯自定义命名格式，而不是强制固定模板。

## 目标用户

- 个人摄影爱好者：希望快速整理日常拍摄、旅行、家庭和活动照片。
- 半职业摄影师：需要按客户、日期、场景或项目组织素材，并长期归档。
- Lightroom 用户：保留 Lightroom 作为修图和导出工具，只自动化其前后的文件管理流程。

## 不做什么

当前阶段不做这些事情：

- 不替代 Adobe Lightroom 的修图、评级、预设管理和导出引擎。
- 不直接修改 RAW 图像内容。
- 不默认上传云端或做多人协作。
- 不强制用户采用单一目录结构。

## 建议的信息架构

一个典型项目目录可以是：

```text
Photos/
  2026/
    2026-04-30_family-trip/
      raw/
      exports/
      archive/
      workflow.json
```

也可以兼容用户已有的分类目录，例如：

```text
Photos/
  Travel/
    Japan/
      2026-04-30_Tokyo/
        raw/
        exports/
```

工具不应强行搬迁已有目录。它应该读取用户指定的“项目目录”，识别其中的 RAW 和导出目录，并记录本次处理结果。

## 核心原则

- 先预览，后执行：重命名、移动、压缩前必须可以 dry-run。
- 可追踪：每次处理生成一份操作清单，便于排查和回滚。
- 不破坏 Lightroom：进入 Lightroom 之前完成路径和文件名稳定化。
- 伴随文件同步：同名 `.xmp`、`.jpg`、`.jpeg`、`.mov` 等伴随文件要有明确策略。
- 跨相机兼容：RAW 扩展名不能只假设一种格式。
