# 标准目录样例与命名策略

## 真实目录样式

当前标准工作目录可以抽象为：

```text
.
└── 20260501-「旅游」重庆
    ├── 20260501-TODO
    ├── 20260501-宁静小区
    ├── 20260501-江北机场T3到达层出租车
    ├── 20260501-重庆人民大礼堂
    └── 20260501-重庆超级加倍飞行营地
```

顶层目录 `20260501-「旅游」重庆` 只是一次整理后的分类容器。工具不应从这里解析“旅游地点”或把 `旅游`、`重庆` 自动拼入文件名。

真正的命名依据是照片文件所在目录。例如：

```text
20260501-「旅游」重庆/20260501-重庆人民大礼堂/DSC09907.ARW
```

这个文件应以 `20260501-重庆人民大礼堂` 作为命名前缀。

## 递归扫描模型

工具应从用户指定的项目根目录开始递归遍历，找到所有支持的照片源文件。

当前版本支持的源文件必须来自扩展名枚举：

- Sony `.ARW`
- DJI `.DNG`

Canon、Nikon、Fujifilm、Olympus、Panasonic 等格式可以保留枚举定义，但当前版本不默认处理。

目录处理规则：

- 不要求 RAW 或 DNG 必须放在 `raw/` 目录下。
- 可以存在任意层级的分类目录。
- 没有照片文件的目录只是分类节点，默认跳过。
- `TODO` 目录默认跳过，除非用户显式指定纳入处理。
- 对每个照片文件，使用“直接包含该照片的目录名”作为 `{folder}`。

示例：

```text
.
└── 20260501-「旅游」重庆
    ├── Day1
    │   └── 20260501-重庆人民大礼堂
    │       └── DSC09907.ARW
    └── Day2
        └── 20260502-洪崖洞
            └── DJI_0001.DNG
```

命名前缀分别是：

```text
20260501-重庆人民大礼堂
20260502-洪崖洞
```

## 推荐重命名模板

默认模板：

```text
{date:YYYYMMDD}-{title}-{date:HHMMSS}_{original}
```

示例：

```text
DSC09907.ARW -> 20260501-大礼堂-184126_DSC09907.ARW
DSC09908.ARW -> 20260501-大礼堂-184127_DSC09908.ARW
DJI_0001.DNG -> 20260501-大礼堂-184512_DJI_0001.DNG
```

这个模板的含义是：

- `{date:YYYYMMDD}`：拍摄日期或目录日期，格式为四位年份、月份、日期。
- `{title}`：目录显示标题，来自 dotfile、批量输入或目录名解析。
- `{date:HHMMSS}`：照片元数据中的拍摄时间，格式为时分秒。
- `{original}`：原始文件名，不含扩展名。
- 扩展名保留原始扩展名。

照片目录名通常已经是 `{日期}-{标题}`，所以最终文件名形成三段式：

```text
{日期}-{标题}-{时间戳}_{原始文件名}.{扩展名}
```

## 同秒照片

同一个照片目录中可能有多张照片拍摄在同一秒。当前样例中就存在这种情况，例如 `DSC09639.ARW` 和 `DSC09640.ARW` 的拍摄时间都是 `00:57:01`。

因为默认模板保留 `{original}`，它们会生成不同文件名：

```text
DSC09639.ARW -> 20260501-江北机场T3到达层出租车-005701_DSC09639.ARW
DSC09640.ARW -> 20260501-江北机场T3到达层出租车-005701_DSC09640.ARW
```

当前版本仍必须在 dry-run 阶段检测最终目标名冲突。可能导致冲突的情况包括：

- 同一目录中混入多台相机且原始文件名重复。
- 重复导入同一批照片。
- 用户自定义模板移除了 `{original}`。

可选冲突增强模板：

```text
{date:YYYYMMDD}-{title}-{date:HHMMSS}_{original}-{seq:02}
```

是否启用序号后缀应由用户显式配置，不能默认悄悄改变用户期望的文件名格式。

## 时间戳来源

时间戳由 ExifTool 读取。正式实现不能依赖 macOS `file` 命令；`file` 只能用于临时人工排查。

ExifTool 字段优先级：

1. `SubSecDateTimeOriginal`
2. `DateTimeOriginal`
3. `SubSecCreateDate`
4. `CreateDate`
5. `ModifyDate`
6. `FileCreateDate`
7. `FileModifyDate`

如果无法得到时间戳，工具必须在 dry-run 中列出这些文件，并阻止执行或要求用户选择回退策略。

已确认的设计依据：

- ExifTool 官方支持 Sony `.ARW`。
- ExifTool 官方支持 `.DNG`。
- 当前真实 Sony `.ARW` 样例中可以读取到 `datetime=2026:05:01 ...`，正式实现需要用 ExifTool 再做一次验收确认。

## 排序要求

该样例中存在相机文件号回绕：

```text
DSC09999.ARW
DSC00001.ARW
```

所以任何需要序号或展示顺序的地方，都必须按拍摄时间排序，而不能按文件名字典序排序。

排序优先级：

1. RAW 或 DNG 元数据中的拍摄时间。
2. 文件系统创建或修改时间。
3. 相机文件号的回绕感知排序。
4. 原始完整路径。

## 实现建议

- 递归扫描项目根目录。
- 按照片文件的直接父目录分组。
- 只处理支持扩展名的照片源文件。
- 不解析顶层目录中的 `「旅游」` 或地点文本。
- 文件名允许中文，但应过滤 `/`、`:`、`\`、控制字符等跨平台非法字符。
- 当文件名长度超过系统限制时，应在 dry-run 阶段报错。
