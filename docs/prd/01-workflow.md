# 整体工作流设计

## 背景

摄影后期流程里，真正消耗注意力的部分通常不是单次文件复制，而是长期重复出现的目录分类、命名一致性、导出整理和归档。这个工具应该把这些步骤标准化，但保留用户对分类方式和命名方式的控制权。

## 推荐流程

### 1. 导入素材

用户将存储卡中的文件复制到电脑上的临时导入目录或目标项目目录。

输入：

- 相机存储卡或本地临时目录。
- 一个目标项目目录。

输出：

- 本地可访问的 RAW 文件集合。
- 可选的伴随文件，例如 `.xmp`、机内直出 JPEG、视频文件。

产品要求：

- 支持用户选择已有目录作为项目目录。
- 不要求工具直接读取相机卡，但后续可以支持“从卡导入到项目目录”。
- 建议保留一次导入校验，例如文件数量、总大小、重复文件提示。

### 2. 分类与目录命名

用户按自己的习惯整理目录，例如按日期、地点、客户、活动或主题分类。

示例：

```text
2026-04-30_Tokyo-Street/
2026-05-01_ClientA-Portrait/
Family/2026-04-30_Birthday/
```

产品要求：

- 工具默认尊重用户已经整理好的目录。
- 目录名可以作为文件重命名模板的 token。
- 不在 MVP 中强制提供自动分类能力。

### 3. RAW 文件重命名

用户在分类完成后运行重命名流程。工具扫描目录内的 RAW 文件，并根据模板生成新文件名。

推荐时机：

- Lightroom 导入之前。

不推荐时机：

- Lightroom 已经建库并引用这些文件之后。

示例模板：

```text
{project_date}_{folder}_{seq:04}
```

生成结果：

```text
20260430_Tokyo-Street_0001.ARW
20260430_Tokyo-Street_0002.ARW
```

### 4. Lightroom 修图

用户将已经稳定命名的项目目录导入 Adobe Lightroom。

产品边界：

- 工具不接管 Lightroom catalog。
- 工具可以记录“已进入 Lightroom 阶段”的状态，但不需要读取 Lightroom 数据库。
- 后续版本可以支持读取导出目录或校验导出数量。

### 5. 导出成片

用户从 Lightroom 导出 JPEG、TIFF 或其他格式到项目目录下的导出目录。

推荐目录：

```text
exports/
  full/
  web/
  selected/
```

产品要求：

- 支持用户指定导出目录。
- 支持检查导出目录是否存在、是否为空、是否有重复文件名。
- 支持将导出文件纳入归档包。

### 6. 压缩归档

用户确认修图和导出完成后，工具把项目目录压缩到归档位置。

推荐归档包命名：

```text
2026-04-30_Tokyo-Street_20260430.zip
```

归档内容建议：

- `raw/`
- `exports/`
- `workflow.json`
- 可选的 Lightroom sidecar 文件或项目说明文件。

产品要求：

- 支持压缩前预览归档内容。
- 支持排除临时文件、缓存文件和系统隐藏文件。
- 支持归档完成后校验压缩包存在且大小合理。

## 状态流转

```text
imported -> classified -> renamed -> editing -> exported -> archived
```

状态含义：

- `imported`：文件已进入电脑。
- `classified`：目录已由用户整理完成。
- `renamed`：RAW 文件名已按模板稳定。
- `editing`：已进入 Lightroom 修图阶段。
- `exported`：导出成片已生成。
- `archived`：项目目录已压缩归档。

状态记录建议写入项目目录下的 `workflow.json`。

## 失败处理

- 如果命名冲突，禁止直接执行重命名。
- 如果目标归档包已存在，默认不覆盖。
- 如果同名 XMP 文件存在，必须跟随 RAW 一起重命名。
- 如果 Lightroom 已经导入过该目录，工具只能提示风险，不应假装可以无损处理。
