# 整体工作流设计

## 背景

摄影后期流程里，真正消耗注意力的部分通常不是单次文件复制，而是长期重复出现的目录分类、命名一致性、sidecar 同步和原始素材归档。这个工具应该把这些步骤标准化，但保留用户对分类方式和命名方式的控制权。

## 推荐流程

### 1. 导入素材

用户将存储卡中的文件复制到电脑上的临时导入目录或目标项目目录。工具支持用户选择已有工作目录，并把常用工作目录保存到用户级 workspace 配置中，便于下次自动加载。

输入：

- 相机存储卡或本地临时目录。
- 一个目标项目目录。

输出：

- 本地可访问的 RAW/DNG 文件集合。
- 可选的 sidecar，例如 `.xmp`、`.acr`，以及与 RAW/DNG 同 stem 的机内 JPEG。
- 可选的其他素材，例如视频文件；当前版本识别但不默认参与重命名。

产品要求：

- 支持用户选择已有目录作为项目目录。
- 支持从本地原始照片目录和 iCloud 原始照片目录中选择项目目录。
- 用户选择过的工作目录保存到 `~/.local/share/photograph-workflow/workspaces.json`。
- 显式传入的项目目录永远优先于已保存 workspace。
- 不要求工具直接读取相机卡，但后续可以支持“从卡导入到项目目录”。
- 建议保留一次导入校验，例如文件数量、总大小、重复文件提示。

### 2. 分类与目录命名

用户按自己的习惯整理目录，例如按日期、地点、客户、活动或主题分类。

示例：

```text
.
├── 20260101-Shanghai_Oriental_Pearl
├── 20260101-ClientA_Portrait
└── Family
    └── 20260101-Birthday
```

产品要求：

- 工具默认尊重用户已经整理好的目录。
- 目录名可以作为文件重命名模板的 token。
- 不提供自动分类能力。

### 3. RAW 文件重命名

用户在分类完成后运行重命名流程。工具从项目根目录递归扫描 RAW、DNG 等照片源文件，并根据照片文件所在目录名和拍摄时间生成新文件名。

推荐时机：

- Lightroom 导入之前。

不推荐时机：

- Lightroom 已经建库并引用这些文件之后。

示例模板：

```text
{date:YYYYMMDD}-{title}-{date:HHMMSS}_{original}
```

生成结果：

```text
20260101-上海东方明珠-080001_DSC00000.ARW
20260101-上海东方明珠-080002_DSC00001.ARW
```

### 4. Lightroom 修图

用户将已经稳定命名的项目目录导入 Adobe Lightroom。

产品边界：

- 工具不接管 Lightroom catalog。
- 工具可以记录“已进入 Lightroom 阶段”的状态，但不需要读取 Lightroom 数据库。
- 工具不管理 Lightroom 导出后的成片。

### 5. 导出成片

用户从 Lightroom 导出 JPEG、TIFF 或其他格式。导出位置由用户自行决定，例如直接导入 Apple Photos 系统相册。

产品边界：

- 工具不指定导出目录。
- 工具不检查导出文件数量。
- 工具不移动、重命名或归档导出后的成片。

### 6. 原始素材归档

用户确认原始素材和 sidecar 命名稳定后，可以把用户传入的项目目录整体压缩到归档位置。归档对象是该目录内的 RAW/DNG 及 sidecar，不包含 Lightroom 导出成片。工具不自动按照片目录拆分多个归档包。

推荐归档包命名：

```text
Shanghai~20260101080001.zip
```

归档内容建议：

- 原始照片目录中的 RAW/DNG。
- Sidecar 文件，例如 `.xmp`、`.acr`，以及与 RAW/DNG 同 stem 的 `.jpg`、`.jpeg`。
- 每个照片目录下的 `.metadata.json`。
- 可选的项目说明文件。

产品要求：

- 支持压缩前预览归档内容。
- 支持排除临时文件、缓存文件和明确的系统垃圾隐藏文件。
- 支持归档完成后校验压缩包存在且大小合理。
- 归档不会修改用户传入的目录名称；压缩包文件名在该目录名后追加 `~{归档时间}`。

## 状态流转

```text
imported -> classified -> renamed -> editing -> archived
```

状态含义：

- `imported`：文件已进入电脑。
- `classified`：目录已由用户整理完成。
- `renamed`：RAW 文件名已按模板稳定。
- `editing`：已进入 Lightroom 修图阶段。
- `archived`：原始素材项目目录已压缩归档。

这是用户工作流状态，用于描述摄影处理过程，不等同于 `.metadata.json.status`。

照片目录下的 `.metadata.json` 只记录目录级命名配置、rename 生命周期状态和文件映射。当前版本不把 `editing`、`archived` 写入 `.metadata.json`。归档不写回 `.metadata.json`，压缩包本身通过文件名中的归档时间区分。

## 失败处理

- 如果命名冲突，禁止直接执行重命名。
- 如果目标归档包已存在，默认不覆盖。
- 如果同 stem 的 `.xmp`、`.acr`、`.jpg` 或 `.jpeg` 文件存在，必须跟随 RAW/DNG 一起重命名。
- 如果 Lightroom 已经导入过该目录，工具只能提示风险，不应假装可以无损处理。
