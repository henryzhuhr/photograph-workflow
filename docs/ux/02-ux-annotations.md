# UX 注解说明

## 为什么需要注解

这套工具处理本地照片文件，核心风险不是“按钮不好看”，而是用户在错误阶段执行了会改文件的动作。因此 UX 需要明确说明：

- 用户当前处在旅程的哪一步。
- 用户下一步可以做什么。
- 系统已经读取、计划或修改了什么。
- 哪些操作只是预览，哪些操作会写入磁盘。
- 失败时为什么停下，用户应该回到哪一步。

注解的目标是让产品、设计、开发和未来 AI 编程助手都能用同一套语义评审原型。

## 注解类型

### 旅程注解

说明完整流程和阶段关系。

适用位置：

- 原型顶部的完整旅程图。
- 桌面/iPad 左侧流程时间线。
- iPhone 横向流程胶囊。

必须回答：

- 当前阶段是什么。
- 前一步完成了什么。
- 下一步会发生什么。
- 用户是否可以跳转到其他阶段。

### 交互注解

说明用户点击、选择或确认后发生什么。

适用位置：

- 选择目录。
- 扫描素材。
- 插入命名占位符。
- 生成预演计划。
- 执行重命名。
- 复制归档名称或执行归档。
- 打开设置或安全中心辅助页面。

必须回答：

- 触发动作是什么。
- 是否有即时反馈。
- 是否会修改文件。
- 是否需要二次确认。

### 系统反馈注解

说明系统如何把状态反馈给用户。

适用位置：

- 扫描结果。
- 目录级状态。
- 可展开的目录树预演计划。
- 文件级错误。
- 附属文件匹配。
- 执行结果。
- 回滚可用性。

必须回答：

- 成功状态显示在哪里。
- 警告是否允许继续。
- 错误是否阻止继续。
- 用户能否定位到具体目录或文件。

### 安全门槛注解

说明危险操作前的阻断和确认。

适用位置：

- 重命名执行。
- 回滚执行。
- ZIP 归档执行。
- 覆盖或删除 workspace 记录。

必须回答：

- 是否必须先生成预演计划。
- 用户确认前是否禁止写磁盘。
- 执行失败后是否仍可追踪原始文件名。
- `.metadata.json` 是否已经记录必要映射。

### 异常注解

说明异常旅程。

适用位置：

- RAW/DNG 元数据不可读。
- 文件名冲突。
- 目录授权失效。
- 附属文件缺失。
- 归档输出路径不可写。

必须回答：

- 用户为什么被阻止。
- 用户可以如何修复。
- 修复后回到哪个阶段。
- 是否允许跳过。

## 当前原型中的注解

`docs/ux/prototype/index.html` 顶部包含一组可见 UX 注解：

- 用户目标。
- 系统反馈。
- 安全门槛。
- 异常分支。
- 六阶段完整旅程图。
- 桌面左下角的设置和安全中心辅助入口。

这些注解属于原型评审层，不是最终应用内必须展示给用户的说明文案。进入真实产品实现时，应把注解转化为更自然的状态、按钮、确认弹窗、错误消息和帮助入口。

## 评审清单

每次修改 UX 时，至少检查：

- 是否仍覆盖准备项目、检查素材、命名规则、执行重命名、Lightroom 后期、归档六个阶段。
- 桌面、iPad、iPhone 是否表达同一条主旅程。
- iPhone 是否能看见当前阶段，并能跳到指定流程。
- 重命名预览是否按目录树聚合，且能展开查看文件级映射。
- 桌面左下角是否保留设置和安全中心入口，且语言归入设置页。
- 所有会写文件的动作是否先预演。
- 元数据不可读是否阻止依赖 `{date}` 的重命名。
- 附属文件是否只处理同名主干文件。
- 用户是否能理解下一步动作和失败原因。
